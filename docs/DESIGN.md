# 设计文档

## 1. 问题形式化

每日派工是**带禁止组合的矩形指派**：

- 质检员 `i ∈ W`（至多去一个任务，空闲代价 0），任务 `j ∈ T`。
- 每个任务要么派给恰好一人，要么顺延，顺延代价 `d_j` 各自独立。
- 允许组合 `(i,j) ∈ A` 有代价 `c_ij`；禁止组合永远不得出现在结果里。
- 所有组合都被禁止的人/任务如实报告为"无法安排"（`unassignable*`）。

LP 形式（`x_ij ∈ {0,1}` 表示派遣，`z_j ∈ {0,1}` 表示顺延）：

```
min  Σ c_ij x_ij + Σ d_j z_j
s.t. Σ_j x_ij        ≤ 1   ∀i      （工人至多一个任务）
     Σ_i x_ij + z_j  = 1   ∀j      （任务要么被派要么顺延）
     x, z ≥ 0
```

对偶：

```
max  Σ_j β_j − Σ_i α_i
s.t. β_j − α_i ≤ c_ij   ∀(i,j) ∈ A
     β_j        ≤ d_j    ∀j
     α_i        ≥ 0      ∀i
```

该 LP 的约束矩阵是全幺模的，极值点即整数解，因此对偶证书 `(α, β)` 足以证明指派最优。

## 2. 求解器（`src/solver/dispatch-solver.ts`）

**不把问题补成方阵再解**，而是直接在原二部图上跑原始-对偶（匈牙利）算法：任务在左侧必须全部被"覆盖"（派给工人，或进入自己的"顺延槽"，代价 `d_j`），工人在右侧可以空闲。

- 维护对偶 `α ≥ 0`、`β ≤ d`、允许组合上 `β_j − α_i ≤ c_ij`，以及紧边构成的匹配。
- 每一轮从未覆盖任务出发长交错树；树扩张停滞时取
  `δ = min(树内任务到树外工人的边松弛, 树内任务的顺延松弛)`，
  树内 `β += δ`、`α += δ`，直到出现新的紧边（增广到空闲工人）或某树内任务顺延槽变紧（沿交错链改派后该任务顺延）。
- 终止时满足全部互补松弛条件：被派组合紧、空闲工人 `α = 0`、顺延任务 `β_j = d_j`，故 `Σβ − Σα = 总代价`，对偶值即证书。
- 复杂度 `O(T·(W+T)·W)`，30×50 规模微秒级。

**确定性**：任务按下标顺序处理，所有取最小操作用严格小于（平手取最小下标），工人边与顺延槽平手时优先工人边。同一输入永远得到同一分配与同一组对偶值（`test/solver.spec.ts` 的 determinism 用例，含大量同值最优解的情形）。

**禁止组合**：禁止对不参与任何计算（无边）。由于"全部顺延"总是可行解，最优解永远不会需要禁止对；测试在随机实例上断言结果不含禁止对。

### 交叉验证与编译方阵（`src/solver/compile.ts`、`src/solver/hungarian.ts`）

另有一个独立的通用方阵匈牙利实现，用于把问题**编译**为 `N=(W+T)` 阶方阵（工人行 + 顺延行；任务列 + 空闲列，禁止项取动态计算的 BIG）后求解。测试断言两个实现在随机实例上最优值一致——两条独立代码路径互相印证。

## 3. 对偶证书（`src/certificate/verify.ts`）

每个版本返回 `alpha`（每人一个）、`beta`（每任务一个）与实际求解的代价矩阵 `effectiveCosts`。调用方可**逐条**独立验证：

| 编号 | 条件 | 含义 |
| --- | --- | --- |
| D1 | `α_i ≥ 0` | 对偶可行 |
| D2 | 工人 i 空闲 ⇒ `α_i = 0` | 互补松弛 |
| D3 | `β_j ≤ d_j` | 对偶可行 |
| D4 | 任务 j 顺延 ⇒ `β_j = d_j` | 互补松弛 |
| D5 | 所有允许组合：`β_j − α_i ≤ c_ij` | 对偶可行 |
| D6 | 被选中组合：`β_j − α_i = c_ij` | 紧约束 |
| D7 | `Σβ − Σα = 总代价` | 目标值一致 |

D1–D6 是对偶可行 + 互补松弛，D7 使原始、对偶目标值相等，由弱对偶性即证最优。禁止组合不参与 D5/D6（它们本就不允许被选中）；"禁止组合绝不在结果中"由一致性检查单独保证。

`POST .../versions/:n/verify` 在服务端重算同样这些条件并报告 `violations`。

## 4. 不变量及其精确陈述

> 关键事实：经典平移/转置不变量在**编译后的方阵**上精确成立；由于"工人空闲"代价恒为 0 且不在用户代价矩阵中，它们在用户层面需要按对应关系表述。

- **行/列平移（编译层，精确）**：对编译方阵任意一行或一列加常数 k，最优匹配集合不变，最优值恰增 k。测试：`test/solver.spec.ts` 的 shift 用例——平移后求得的匹配在原矩阵上仍是最优，且最优值差恰为 k。
- **列平移（用户层）**：任务 j 的整列代价连同其顺延代价 `d_j` 一起加 k（每个方案恰好覆盖任务 j 一次：派人或顺延），最优分配不变、最优值增 k。测试直接调主求解器核对。
- **工人行平移（说明）**：只平移 `c_ij` 而不动"空闲代价 0"时，最优分配**可能**改变（空闲方案相对变便宜）——这是模型语义决定的，不是求解器缺陷；对应的精确不变量即编译层行平移（工人行包含其空闲列的 0）。
- **转置（编译层，精确）**：编译方阵转置后最优值相同（匹配 σ ↔ σ⁻¹ 双射）。用户层面人与任务互换角色时，由于顺延代价依附于任务、空闲代价恒 0，转置问题一般不是同一个派工问题，故该不变量在编译层核对。

其余必须成立的不变量：最优总代价 ≤ 任何贪心分配（测试用" cheapest-first "贪心对照）；禁止组合绝不出现在结果中；全禁止的人/任务如实报告（`unassignableWorkers/Tasks`，且任务顺延、人员空闲）。

## 5. 重排规则：稳定性惩罚 ρ

**选定的规则**：变动后求解

```
min   rawCost(plan) + ρ · (#与上一版相比被改派的人数)
```

- `rawCost` = 真实代价下的总代价（派遣代价 + 顺延代价）。
- "被改派"：任务 A→任务 B、任务→空闲、空闲→任务都算一人次；因变动离场的人不计。
- ρ ≥ 0 是"改派一人"的代价，**当日级别参数**（`reassignmentPenalty`，默认 10），也可在单次变动上覆盖。ρ = 0 退化为纯重新最优。

**实现**：把惩罚折进代价矩阵（保持同一求解器与证书机制）——上一版在任务 j0 的人：保留组合代价 `c−ρ`、其余不变、常数项 `+ρ`；上一版空闲的人：所有组合 `c+ρ`。则 `惩罚目标 = 求解器目标值 + 常数`，每个版本同时记录 `rawCost` 与 `penalizedCost`，证书证明的是惩罚目标的最优性，`verify` 额外核对 `penalizedCost = rawCost + ρ·改派人数`。

**可验证的声称**：返回方案在**所有可行方案**中使 `rawCost + ρ·改派人数` 最小。`test/replan.spec.ts` 在小规模实例上穷举全部分配逐一核对该最小值；`test/dispatch.service.spec.ts` 在随机变动序列上对每个版本用从头求解复核惩罚目标值。

**何时明显偏离（裸）最优**：由 `惩罚目标(返回) ≤ 惩罚目标(任意)` 得 `rawCost(返回) ≤ rawCost(裸最优) + ρ·K`，K 为裸最优方案相对上一版的改派人数——偏离上界随 ρ 线性增长。典型场景：某人所有组合的代价同时大幅下降但降幅 < ρ 时，方案会保留其旧指派（这在业务上正是想要的：省一点分数不值得让一个人在路上被电话改派）；若希望此时追最优，把该次变动的 ρ 调小即可。另一个极端：ρ 很大时方案几乎不动，可能长期保留明显更贵的指派。

## 6. 增量修复（`src/replan/incremental.ts`）

只因一个变动从头求解在大规模时偏慢，所以变动处理**复用上一版的匹配与对偶值**热启动：

1. 把上一版匹配/对偶映射到新下标（离场的人/取消的任务被移除，新任务 `β = +∞` 未匹配）。
2. 解除不再合法的匹配对（被改禁、或代价改写后不再紧的边）。
3. 恢复对偶可行性：空闲工人 `α` 归零（证书要求），并按 `β_j := min(d_j, min_i α_i + c_ij)` 下调 β；下调可能破坏该任务当前匹配边的紧性，则解除该对并级联（修复期间匹配只减不增，必终止）。
4. 对所有未覆盖任务重跑第 2 节的原始-对偶增广。

**正确性论证**：第 3 步结束时对偶可行、存活匹配边皆紧；第 4 步就是从头求解的算法，只是从一个可行对偶与合法部分紧匹配出发，原始-对偶不变式保持到终止，故结果对新问题最优。因此**增量修复与从头求解的目标值必相等**——`test/replan.spec.ts` 在数百个随机实例×随机变动（含稳定化与未稳定化两种）上断言两者目标值一致，并校验增量结果的证书；`test/dispatch.service.spec.ts` 在服务层对随机变动序列的每个版本复核。

## 7. 版本管理与并发

- 早上 `POST /dispatch/days` 生成版本 1（纯代价最优，无稳定对象）；之后每个变动生成下一版本，记录触发的变动、与上一版的差异（`diffFromPrevious`）、完整当日数据（**每个版本自包含**）、对偶证书。
- 任意两版本可比较：`GET .../diff?from=a&to=b` 返回被改派的人（含变成空闲/重新上岗）、任务状态变化、人员/任务的增删。
- **并发行为（已选定）**：变动必须带 `baseVersion`；不等于当前版本 ⇒ **拒绝**，返回 409 与 `currentVersion`，**不做自动重放**。两个调度员同时提交时，`(date, version)` 唯一索引保证只有一个插入成功，输家同样收到 409 + 当前版本。由此版本严格按序生成、无空洞。
- **重启恢复**：全部状态（当日配置 + 所有版本）都在 MongoDB；每个版本自包含当日数据，当前版本 = 最大版本号，无需任何日志重放，重启后直接恢复。测试用同一数据库重建应用实例核对。

## 8. 模块结构

```
src/
  solver/        求解器：dispatch-solver（主）、hungarian（交叉验证）、compile（编译方阵）、types
  certificate/   对偶证书校验（纯函数，D1–D7 + 一致性）
  replan/        重排策略：penalty（稳定性惩罚变换）、incremental（增量修复）
  dispatch/      领域：change（变动应用与校验）、errors、dispatch.service（编排）
  version/       版本快照与差异（diffPlans）
  persistence/   MongoDB 连接与仓储（days / versions，唯一索引）
  api/           REST：controller、异常过滤（字段级错误）
test/            Jest：solver / replan / dispatch.service / api.e2e
```
